# FG WGC 320 EarlyFlow — Input Aware (experimental)

Based on the exact uploaded EarlyFlow source ZIP. No game injection, mouse injection, GPU readback, additional GPU pass or added frame queue. The existing real-frame path, WGC, dual NvOFA 4x4 FAST (cost off), and pacing remain in place. Generated frames now optionally consume late relative mouse deltas through a single existing draw. The shader adds a camera-only sample when correction is active; there is some extra pixel-shader work. This is not NVIDIA Reflex 2.

## Build / try
1. Extract to a new directory. Use Visual Studio 2026 or compatible MSVC x64 and a recent Windows SDK supporting the original WGC code. Run `Build-InputAware.cmd` (or `Build.cmd` from an x64 developer prompt). The original NGX SDK download script still needs Internet access to build, even when NGX is off.
2. Open `bin\FG.exe`. Leave Reflex 2 Frame Warp unchecked. The new `Late mouse input (FG)` checkbox defaults ON and is live; uncheck it to compare with baseline. The two modes are mutually exclusive. Original NGX runtime is not required at run time for the new mode; for the old NGX mode copy the original `FrameWarpRuntime` folder from the supplied executable ZIP beside `bin\FG.exe`.
3. Try CS2 at 60 FPS, Dynamic 320; use your usual 800 DPI, 1.5 sensitivity and 1000 Hz polling. Compare stationary aim, slow turns, abrupt stops and direction reversals. Try e.g. radius 8 / feather 8 if the crosshair moves. Off mode does not generate frames or apply the new correction.
4. Compare checkbox on/off at identical settings. If real/generated transitions shake or edges/HUD distort, disable the new option. The shader estimates camera projection and has no game HUD/depth/motion-vector access. It does not alter shot timing, movement simulation, or hit registration.

## Algorithm and assumptions
The render-thread raw input handler records cumulative relative mouse counts with QPC receipt timestamps; only the focused game's input is recorded. History resets on refocus. Before each generated draw, up to 64 pending raw input messages are drained without waiting. The previous/current WGC source timestamps are shifted back by an assumed 5 ms to estimate game input sampling. The camera delta expected from NvOFA extrapolation is the preceding input delta times the existing extrapolation horizon. The residual = actual new mouse delta minus expected camera delta. Apply a bounded first-order inverse camera rotation to the existing extrapolated sampling UV. If object flow is unreliable, use the bounded camera-only mapping instead; scene cuts, center mask and out-of-bounds handling remain. Assumes sensitivity 1.5, m_yaw/m_pitch 0.022, vertical FOV about 73.74 degrees and source texture aspect ratio (if WGC is already stretched this may be inaccurate). Both camera correction vectors are limited to 4 degrees. No game-provided input-sample time; 5 ms is a starting assumption, not measured latency. Generated frames still require ready optical flow and the original scheduler. Real frames remain unchanged by the new mode, so visible correction can snap on arrival of a real frame.

## Verification
Portable C++20 unit tests in `tests/late_input_test.cpp` passed on Linux: history, constant movement, abrupt stop, idle, reversal, input between frames, clamp, overflow, reset. Windows app and HLSL have NOT been compiled or run in this environment. No new EXE is included and no performance or visual-quality improvement is claimed until tested on Windows. Original source UI and runtime remain otherwise unchanged; GitHub Actions builds the Windows executable on pushes to `fg-wgc-320-earlyflow-input-aware`. Check the Actions run for the actual compilation result.
